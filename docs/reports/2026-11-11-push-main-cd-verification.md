## Nội dung vận hành

[Checklist](../operations/release-checklist.md), [release runbook](../operations/product-release-runbook.md), [rollback runbook](../operations/product-rollback-runbook.md), [deploy boundary](../../deploy/README.md) và [readiness](../agent/READINESS.md) đã được đối chiếu với workflows hiện hành trước sửa; giữ lại contract manual/attestation/backup/SSH cũ và cập nhật daily path.

Sau setup một lần, operator merge local code đã review rồi `git push origin main`. Release thường không nhập SHA/run/artifact ID, không bấm approval thủ công. `main-release.yml` nhận full `github.sha`, preflight current state rồi quality → immutable GHCR → backup → deploy → verify. Build và backup thực tế chạy song song sau quality; deploy cần cả hai đạt. Exact run/attempt/artifact IDs/archive digest và image digests đi bằng reusable outputs, không dispatch/poll hoặc chọn latest cho đường tự động.

VPS pull API/Web `@sha256:<64 hex>` và kiểm RepoDigest trước migration; pinned PostgreSQL không tự nâng version. Normal release luôn yêu cầu target-bound, fresh, retained, restore-verified `BACKUP`. Bootstrap/`INITIAL_EMPTY_DEPLOYMENT` là route riêng, không fallback khi mất volume/DB/marker. Concurrency không cancel active mutation; pending có thể superseded, không hứa release mọi commit. Rerun verified SHA có thể `already-deployed`; uncertain state phải incident.

## Receipts phải quan sát mỗi push

- Summary `MKW push-main release`: full release SHA, correlation `<run_id>-<attempt>`, operation `<run_id>-<attempt>-<SHA>`, stage results; `release-status` không đợi/tổng hợp recovery, phải xem recovery summary riêng.
- `mkw-release-<SHA>`: exact artifact ID/owner/run/attempt/archive digest, manifest/checksum, API/Web/PostgreSQL digests, SBOM/provenance/attestation status. Retention workflow 30 ngày; không chọn artifact tùy ý nếu expired.
- `mkw-backup-<run_id>-<attempt>`: `backup-ready.json`, encrypted dump/checksum, target host/database/path/project, snapshot UTC, restore verification, age/retention. Fresh rollback backup có suffix `-app-rollback`; không tái dùng pre-release backup cho recovery.
- Server receipt trong `receipts/`; `shared/current-state.json`/`shared/last-known-good.json` chỉ promote khi runtime/schema/ownership/attestation đầy đủ. Deploy chưa tự upload server receipt: thu thập qua route được phép, không suy thiếu receipt là chưa mutate.
- `mkw-post-deploy-receipt-<SHA>`: verification receipt/rollback signal; khi recovery chạy, `mkw-auto-rollback-<run_id>-<attempt>` chứa `auto-rollback-evidence.json`. Không chứa key/token/password/DB URL hoặc dump plaintext.

## Incident, retry và recovery

Artifact/attestation/registry/fingerprint/backup mismatch phải dừng trước migration. Timeout/cancel giữ URL/correlation; cancel request không chứng minh remote stopped. Kiểm current state và active transaction trước retry; không blind retry migration/rollback hoặc bỏ SSH pin/clock/retention gate.

Auto rollback chỉ thử một lần khi application đã mutate và đủ previous LKG, canonical artifact/attestation, current operation/ownership/runtime, fresh restore-verified BACKUP của DB hiện tại, PostgreSQL container/digest và schema/migration/data-operation proof. Chỉ API/Web `--no-deps api gateway`, không migrate từ old image, restore DB, đổi PostgreSQL hoặc down-migrate. `recovered-by-app-rollback` vẫn giữ original pipeline Failed.

Migration changed/failed/unknown, unknown data operation/side effect hoặc thiếu producer receipt/previous state/backup/attestation, PG mismatch/interleaving → `incident-required`. Manual incident giữ maintenance, evidence, tạo BACKUP mới và xác nhận compatibility trước rollback. Database restore/down migration thuộc incident route có approval riêng; restore vào DB mới, verify/revoke sessions và cutover theo [backup/restore](../operations/product-backup-restore.md), không giả auto recovery dữ liệu.
