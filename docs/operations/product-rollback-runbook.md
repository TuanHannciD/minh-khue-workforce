# Runbook rollback ứng dụng thủ công

Push-main không tự rollback ứng dụng hoặc restore database. Giữ stage, operation ID, SHA, digests và backup identity khi build/backup/migration/health/smoke thất bại. Route này dùng environment `production-recovery`, approval hiện hành và `refs/heads/main`.

1. Dừng release mới hoặc quyết định maintenance theo incident. Tạo `BACKUP` mới của **database hiện tại**, đúng target, có restore verification/freshness/retention. Không dùng `INITIAL_EMPTY_DEPLOYMENT`. Snapshot SHA độc lập SHA ứng dụng cũ.
2. Chạy `rollback.yml` từ trusted current `main`, cung cấp exact old release SHA, producing run/attempt/artifact và backup run/artifact mới. Resolver kiểm canonical producer, archive digest, manifest/metadata, attestation và snapshot; old source chỉ cung cấp Compose/operator như dữ liệu. Entrypoint/helpers lấy từ trusted current controls.
3. Xác nhận API/Web cũ tương thích schema hiện tại. Bundle đi qua private operation staging và inventory; một server flock giữ từ admission đến receipt. Dưới lock, kiểm lại canonical backup và running PostgreSQL digest **trước config/apply**. Mismatch dừng `78`; không đổi PostgreSQL để làm guard đạt.
4. Chỉ apply `api gateway --no-deps` bằng old immutable digests. Route rollback không chạy migrate/restore, không `up db`, không thay PostgreSQL container/volume/data/schema/migration history. Không reset/down-migrate/xóa volume. Database recovery là quyết định và runbook riêng.
5. Verify exact rollback operation ID/SHA/control SHA, image IDs/digests, migration status đọc, health và HTTP smoke. Giữ cả receipt của incident cũ và operation recovery; receipt phải ghi `application-only`, `databaseRecovery: false`. Receipt thiếu/failed không là success.
6. Nếu compatibility/schema/data còn chưa rõ, dừng route. Restore vào database mới, kiểm chứng rồi cutover chỉ theo approval và [backup/restore runbook](product-backup-restore.md) riêng; không restore đè database đang chạy từ workflow rollback.

Retry dùng operation ID mới; giữ exact artifact IDs/digests và lý do operator. Không retry khi lock còn giữ, không xóa operation uncertainty hoặc chọn receipt mới nhất theo thời gian. Config nhiều file không là transaction: có thể API env đã publish nhưng Compose cũ; migration lỗi có thể đã đổi DB. Recovery cần kiểm runtime và receipt phase. Release legacy thiếu inventory/có bytes khác không được tự adopt/overwrite; cần chuyển tiếp riêng trước live rollout. Báo cáo thiết kế automatic rollback cũ giữ để audit.
