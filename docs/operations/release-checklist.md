- [ ] Kiểm attestation signer `build-release.yml` và mode ở cả build/deploy. Required mode phải fail closed; SBOM/checksum không thay signature verification.

Chỉ gọi **Activated** sau khi các gate trên có evidence đúng target. Local implementation/evidence không chứng minh activation hoặc release production; xem [Task 5 verification](../reports/2026-11-11-push-main-cd-verification.md).

## Daily flow — merge local → push main

1. Merge local thay đổi đã review, chạy checks phù hợp, rồi `git push origin main` khi có quyền. Release thường **không nhập SHA/run/artifact ID và không cần approval thủ công** sau khi activation policy đã đáp ứng.
2. `main-release.yml` là entry `push main` duy nhất, không path filter. Full `github.sha` cố định source/control SHA cho reusable stages. Preflight đọc current-state; `quality` đạt mới mở build immutable GHCR và backup (hai job chạy song song); deploy chỉ chạy khi **cả build và backup** đạt, sau đó verify. Luồng nghiệp vụ là quality → immutable GHCR → backup → deploy → verify.
3. Build/backup outputs forward exact run/attempt/artifact ID/name/archive digest, API/Web digest và pinned PostgreSQL; operator không chọn “latest”. Backup bắt buộc đúng target, fresh, retained và restore-verified trước mutation. VPS pull exact digest và kiểm `RepoDigest` trước migration.
4. Concurrency `mkw-production-release`, `cancel-in-progress:false` giữ một transaction; remote flock là boundary cuối. Push mới không hủy active migration; pending cũ có thể bị superseded, không hứa release mọi commit. Recheck stale source trước mutation; rerun SHA verified có thể `already-deployed`, unknown state là incident.
5. Đọc `MKW push-main release` summary theo correlation `<run_id>-<attempt>` và operation `<run_id>-<attempt>-<SHA>`, rồi receipts bên dưới. `release-status` tổng hợp prerequisite và verify; recovery có summary/artifact riêng, không được suy `failed` đã được recovery. Lỗi bất kỳ prerequisite không mở stage sau.

## Cấu hình và scope

Registry vars trên environment `production`: `MKW_REGISTRY_HOST=ghcr.io`, `MKW_REGISTRY_VISIBILITY=public|private`, `MKW_REGISTRY_PULL_USERNAME`, `MKW_REGISTRY_PULL_TOKEN_FILE` (mặc định `/home/deploy/mkw/shared/secrets/ghcr-pull-token`). Username có thể đọc từ file `shared/secrets/ghcr-pull-username`; chưa cấu hình visibility thì helper suy private khi có file username, còn lại public. Kiểm explicit actual policy; không coi default là bằng chứng package public. Token chỉ `read:packages`, không có write; không in nội dung file. Auto path dùng `MKW_BACKUP_MAX_AGE_SECONDS` mặc định `86400`; không nới tuổi/retention để bỏ gate.

## Coordinator thủ công — dry-run/bootstrap/recovery

Route thủ công không thuộc daily flow. Ví dụ input: SHA `47e1d7fd6486cec7169874fb85110d0418db4eed` chỉ là ví dụ input, chưa có xác nhận build artifact/GitHub CI cho nó. Sau các approval/gate ở trên, từ checkout đã tin cậy:

```bash
gh workflow run release-pipeline.yml --ref main \
  --field release_sha=47e1d7fd6486cec7169874fb85110d0418db4eed \
  --field mode=release --field backup_kind=BACKUP
```

Đổi `mode` có ý nghĩa sau; cả ba vẫn cần build artifact và dispatch backup thật, environment approval/SSH. Không chạy ví dụ này như local test.

| Mode                 | Deploy entrypoint và verifier                                                                                                                                                                                                                                                                                                                                         |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dry-run` (mặc định) | SSH preflight Docker Compose, input và dung lượng `/home` ít nhất 1 GiB; không apply ứng dụng. Verifier kiểm artifact/SHA, receipt `skipped-preflight-only`, không runtime PASS.                                                                                                                                                                                      |
| `bootstrap`          | Tạo thư mục/lock và hai secret env files nếu chưa có; giữ secret có sẵn, yêu cầu đủ cả hai files. Không khởi chạy release hoặc migration; verifier chỉ preflight. Đây là mutation server cần approval.                                                                                                                                                                |
| `release`            | Kiểm manifest/checksum/digests/backup/attestation, truyền artifact đã chọn và current policy; remote revalidate backup bằng UTC thật dưới deploy lock trước mutation và trước migration. Chạy Prisma `migrate deploy`, Compose, health/smoke rồi receipt. Verifier kiểm running image IDs/digests, migration status, gateway/startup; cần đọc kết quả job và receipt. |

Direct child dispatch giữ tương thích preflight: `deploy.yml` nhận `dry-run`/`bootstrap` với `mode` và `release_sha`, các run/artifact IDs và backup kind/name là optional ở dispatch; `release` bắt buộc run IDs, exact release/backup artifact IDs, backup name và kind trước download/SSH. `post-deploy-verify.yml` preflight có thể bỏ artifact ID/run ID, chỉ checkout source và ghi receipt `skipped-preflight-only`; nếu cung cấp exact ID thì kiểm manifest/SHA. Coordinator luôn cung cấp exact IDs ở cả ba mode. Preflight không có artifact không được coi là artifact/runtime verification.

Coordinator chạy policy từ `main`, chọn artifact theo tên + manifest `releaseSha`, `build-metadata.sourceSha`, source repository và successful canonical `build-release.yml` run; không lấy “latest” hoặc coi workflow-run `head_sha` là source SHA. Không có hoặc có nhiều match đều dừng. Runner và remote gate so `databaseIdentity.host` với trusted `MKW_SSH_HOST`, database `mkw`; initial-empty evidence phải có `targetIdentity` đúng `${MKW_SSH_HOST}/${MKW_DEPLOY_PATH}/${MKW_PROJECT_NAME}` (giữ dấu `/` đầu path nên có `//` sau host), `databaseIdentity=mkw`. Remote recheck dưới lock trước env/render/migration. Thiếu target policy dừng trước mutation. Mỗi backup/deploy/verify dispatch được gắn correlation và exact run/attempt; coordinator rerun dùng run attempt mới, không tái sử dụng cùng marker.

## Bằng chứng phải giữ

- [ ] Ghi release SHA, build run ID, release artifact ID/name, manifest/checksum, API/Web/PostgreSQL digests và SBOM/provenance/attestation status. Artifact release giữ 30 ngày theo workflow; expired artifact cần build/route phê duyệt mới, không chọn bản tùy ý.
- [ ] Ghi backup run ID **và attempt**, exact artifact ID/name `mkw-backup-<run_id>-<attempt>`, metadata `backupId=mkw-<run_id>-<attempt>`, snapshot UTC, kind, SHA provenance, database identity, encrypted dump SHA-256/size và `retentionUntil`. Artifact `BACKUP` chứa `database.dump.enc`, checksum và `backup-ready.json`; empty deployment chỉ có metadata.
- [ ] Freshness mặc định **86400 giây (24 giờ)** ở coordinator; deploy input `backup_max_age_seconds` mặc định cùng giá trị, rollback cố định 86400. Coordinator không có input đổi tuổi. Created/empty checkedAt không được ở tương lai, không quá tuổi và retention phải còn hạn; chờ approval lâu có thể làm backup hết hạn. Không nới clock/retention hoặc sửa metadata để qua gate; tạo lại backup thật.
- [ ] Giữ deploy/verify run IDs, server receipt trong `receipts/`, artifact `mkw-post-deploy-receipt-<SHA>` gồm `verification-receipt.json`/`rollback-signal.json`. Deploy chưa tự upload server receipt; operator thu thập qua route được phép và loại secret. Recovery có `mkw-auto-rollback-<run_id>-<attempt>`/`auto-rollback-evidence.json`; fresh rollback backup có suffix `-app-rollback`. State tại `shared/current-state.json` và `shared/last-known-good.json` chỉ được promote khi runtime/schema/ownership/attestation đầy đủ; thiếu receipt không chứng minh chưa mutate. Freshness là point-in-time, không bảo đảm chưa có write sau snapshot.

## Khi thất bại và rollback

Artifact không xác định, checksum/SHA/backup/attestation sai: dừng, giữ IDs/log an toàn, xử lý nguyên nhân rồi tạo run mới. Lỗi SSH/fingerprint không được bỏ StrictHostKeyChecking. Deploy/verify/rollback lọc từng key-scan line bằng exact SHA256 fingerprint, yêu cầu file pinned không rỗng và dùng riêng file này cho mọi SSH/SCP (global known_hosts bị vô hiệu hóa). Post-deploy chỉ chạy verifier từ current policy, không thực thi verifier trong release source. Coordinator có deadline tổng 150 phút (job cha 180 phút), mỗi stage gồm dispatch/discovery/approval/queue/runtime: backup 50 phút, deploy 50 phút, verify 30 phút; discovery tối đa 5 phút trong budget stage. Mỗi API/download/unzip/dispatch/cancel process có timeout 30 giây để chừa margin cho API latency/cleanup. Child timeout yêu cầu cancel exact run ID khi API hỗ trợ; cancel request không chứng minh termination. Nếu cancel thất bại/không hỗ trợ, lỗi ghi run URL còn có thể active; nếu chưa discovery, ghi correlation và workflow URL. Không dispatch stage sau. Coordinator dừng khi child workflow thất bại/timeout hoặc run identity thay đổi; trước retry kiểm các run đang chờ approval/đã mutate để tránh release lặp.

Trong push-main, deploy/verify failure mở reusable `automatic-rollback.yml`; manual coordinator chỉ phát signal, không tự dispatch rollback. Auto rollback chỉ thử một lần khi application đã mutate, previous LKG/ownership/artifact/attestation đầy đủ, current runtime đúng failed operation, fresh current-DB BACKUP và PostgreSQL/schema/migration/data-operation proof đều hợp lệ. Chỉ API/Web `--no-deps api gateway`, không migration từ old image, không đổi DB container/digest, restore hoặc down-migrate. Unknown data operation/migration, thiếu evidence hoặc interleaving → `incident-required`; thành công → `recovered-by-app-rollback`, pipeline gốc vẫn Failed. Journal hiện unknown do chưa có data-operation producer, nên không hứa recovery tự động production. Receipt `runtimeVerification:attempted` không có nghĩa thành công; xem `result`, startup/migration evidence. Migration failure có thể xảy ra trước server receipt; thiếu receipt không chứng minh chưa mutate. Operator giữ traffic/maintenance theo incident approval, không tự xóa migration ledger hoặc chạy down migration.

Rollback workflow hiện hành cần `old_release_sha`, `old_release_run_id`, **`old_release_artifact_id`**, **`backup_run_id`/`backup_artifact_id` của BACKUP mới từ DB hiện tại**, và `reason` chứa incident/approval xác nhận app cũ tương thích schema hiện tại. Snapshot SHA là provenance của DB hiện tại, **không phải yêu cầu bằng SHA app cũ**; không dùng backup lịch sử gắn app cũ hoặc empty marker làm thay thế. Workflow kiểm host/DB `mkw`, restore verification, tuổi/retention rồi truyền metadata tới remote.

Dispatch rollback chỉ từ `refs/heads/main`; ref khác dừng trước checkout/API/SSH. Trusted API resolver kiểm exact old artifact ID còn hạn, ownership đúng run, successful canonical `build-release.yml` producer và manifest/build-metadata source SHA/repository. Không chọn artifact chỉ theo tên. Current controls/compose checkout `main`; receipt `controlSha` lấy actual checkout commit, old manifest/API/Web digests là data. Dưới deploy lock, guard đọc đúng một PostgreSQL container đang chạy theo project/service labels và so digest với old manifest; thiếu/không rõ/mutable/mismatch đều dừng trước env/render/Compose mutation. Digest trùng mới giữ DB container, `up --no-deps api gateway`; forward migration gate vẫn chạy. Digest trùng **không chứng minh app/schema/data compatibility**: operator phải xác nhận riêng trước approval.

Giữ rollback runner artifact `mkw-rollback-receipt-<oldSHA>` và server receipt; scope `application-only`, `databaseRecovery:false`. Không có restore dữ liệu/down migration/đổi PostgreSQL tự động. Không tương thích hoặc cần khôi phục dữ liệu: dừng route này, restore vào DB mới, verify/revoke restored sessions và cutover theo approval riêng. Sau rollback kiểm lại health/smoke/runtime đúng manifest cũ theo [rollback runbook](product-rollback-runbook.md).
